# Sprint Planning Checklist

**Sprint:** [number or name]
**Dates:** [start] to [end]
**Sprint goal:** [one sentence: what will be true at the end of the sprint?]

## Before the meeting (1 to 2 days earlier)
- [ ] Backlog is in priority order
- [ ] Top stories have clear acceptance criteria
- [ ] Designs for the top stories are ready
- [ ] Open questions from the client are answered
- [ ] Team availability checked (leave, holidays, other projects)
- [ ] Carry-over work from the last sprint is reviewed

## In the meeting
- [ ] Share the sprint goal first
- [ ] Walk through each story. Developers and QA ask questions
- [ ] Estimate each story with the team
- [ ] Pick stories that fit the team's real capacity
- [ ] Leave about 15% of capacity for bugs and surprises
- [ ] Name one owner for every story
- [ ] Note dependencies (another team, a client decision, an API key)
- [ ] Agree what "done" means (coded, tested, reviewed, deployed to staging)

## After the meeting
- [ ] Sprint board is updated, with every story assigned
- [ ] Sprint goal and scope are shared with the client
- [ ] Risks and blockers are written down
- [ ] Daily stand-up time is confirmed
